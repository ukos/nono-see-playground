# SEE シナリオチェック仕様（8観点 × 8軸・SEE版）

- 作成：2026-11-25
- 元にしたもの：NONO Stage Actor「シナリオチェック仕様（8観点 × 8軸）」（2026-11-25 版）
- 対象：SEE の「国と地域」1つずつ（`world.js` の1件）
- 目的：国を量産するときに、惰性で機械的に作らないための制作ゲート

---

## 1. 仕組みの概要

1つの国につき、次の4点セットでチェックする（Stage Actor と同じ）。

| # | 要素 | 形式 | 役割 |
|---|---|---|---|
| (1) | 8観点 | 各 ○／△／× | 正しく作られているか |
| (2) | 8軸 | 各 1〜5点、合計40点 | 旅人にとって、その国が面白く残るか |
| (3) | 感情曲線 | 住人との会話ごとに5指標を 1〜5 | 8軸の点の根拠 |
| (4) | 不具合 | 台詞の引用つきで列挙 | 具体的な誤り |

加えて、SEE では (0) 機械チェック（`tools/check.js`）を先に通す。機械チェックでエラーが残っている国はレビューしない。

## 2. Stage Actor との違い（SEE の前提）

SEE は「演目を観る劇場」ではなく、「旅人が通り過ぎる世界」。台本の読み替えは次のとおり。

- 1作品 → 1つの国。場面 → 住人1人との1回の会話
- 狂言回し → nono（旅人）。nono は主役ではなく、住人の日常に少しだけ関わって先へ進む
- 物語は語り切らない。1つの国のエピソードは数分以内で、余韻を残す（企画書 §4.2）
- 戦闘はない。対立と賭けは「小さな日常の困りごと・すれ違い・秘密」で作る
- 国の終わりに nono の「気づき」が言葉で1つ残る。数値の成長はない
- 行きと帰りで同じ場所の意味が変わることが、作品の核（企画書 §3）
- 役者の見た目と役の一致は評価しない。笑顔や悲しい顔の絵がない役者は通常顔で表示されるので、表情指定も指摘しない
- 住人は人間が基本。人間でない者（人魚・妖怪・ライバル本人など）は特別枠（伝説＝うわさの正体が本当にいた／ゲスト）としてだけ出る。特別枠が出る国では、その者が出る必然があるかを「固有性」と「旅の連なり」で見る

## 3. 入力と読み方

- 読むのは `review/tx/<国ID>.txt` のみ（`tools/tx.js` が `world.js` から書き出す）。`world.js` や過去のレビュー結果は見ない
- 台本は、旅人が実際に歩いた順の記録。`〔行き〕` は初めて東へ歩いたとき（国の中での行き来を含む）、`〔帰り〕` は世界の東端まで行ったあと西へ戻ったときの会話
- 書式：`== 国: 名前（土地の呼び名）`、`-- 住人名 @位置`、`住人名(表情): 台詞`、`nono: 台詞`、`★気づき: 文`
- 他の国の出来事に依存する台詞（「ユイ」「レイ」の正体、運び屋ミツなど）は、台本の注記を手がかりに、国をまたいだ前提として読む

## 4. 8観点（○ 問題なし／△ 軽い問題／× 重い問題）

1. **整合性** — 国の中と、国をまたいだ設定の矛盾。時系列（同じ人物が同時に二か所にいる等）、言っていない情報を知っている、行きと帰りの食い違い
2. **固有性** — その国でしか起きない話か。人物の名前と小道具を差し替えれば別の国でも成り立つ話、他の国と同じ骨組み（「A が半分話す → B が残りを話す → A に戻ると格言」の反復）、同じ言い回しの使い回しを検出する
3. **情報設計** — 旅人が「誰と話せば先に進むか」「何が気になるか」を、指示なしで自然に分かるか。説明の過不足
4. **実装可能性** — 機械チェック（`tools/check.js`）の結果。素材の実在、ID の一意性、フラグの立て忘れ・読むだけのフラグ、到達できない気づき、60字超の台詞
5. **体験品質** — 短い日常話として成立しているか（入り・小さな転換・余韻）。旅人が数分で通り過ぎられる長さか
6. **安全・権利** — 原作（著作権の切れた演目）の文章を写していないか、実在の国・民族・宗教を笑いものにしていないか、子どもが見て問題ないか
7. **土地の手触り** — 遠景・建物・天候・時間帯と会話が噛み合っているか。その土地の暮らし（食・仕事・気候）が会話に出ているか。背景だけ差し替えた国になっていないか（Stage Actor の「再利用性」の読み替え）
8. **旅の連なり** — 国をまたいだ重複、再登場人物の扱い、伏線と回収、気づきどうしの重複や矛盾

## 5. 8軸（各1〜5点、合計40点）

1. **Hook（入り）** — 国に入って最初に話す相手が、気になること（ちょっとした謎・困りごと・違和感）を出すか。ただの挨拶と土地の説明で始まっていないか
2. **Stakes（小さな賭け）** — 住人が何を気にしていて、どうなると困るかが分かるか。日常の大きさのままで、気持ちが動く賭けがあるか
3. **Character Voice** — 住人ごとの口調・価値観・反応の違い。説明役に固定されていないか。ゲスト（ユイ、レイ、WATCH）がその国で生きているか
4. **Surprise & Payoff** — 二人目の話や帰り道で、一人目の話の見え方が変わるか。突然の新設定で落としていないか
5. **Pacing & Variety（歩く間）** — 話の長さと間。説明・笑い・静けさが変わるか。毎回同じ型の会話が続いていないか
6. **Resonance（余韻と気づき）** — 気づきが台詞の説教ではなく、出来事から自然に出ているか。言わずに残す部分があるか
7. **SEE らしさ** — このゲーム固有の見せ場。具体的には：
   - 行きと帰りで、同じ人・同じ場所の意味が変わるか
   - 噂・証言・実見で、見え方が変わるか（確信度の遊び）
   - 旅人の位置（通り過ぎる者、よそ者）が話に効いているか
   - 歩いて行って戻る、という移動そのものが話になっているか
   - 天候・時間帯・遠景が、話の一部になっているか
8. **Memorability** — その国を一言で思い出せるか（小道具・反転・決め台詞）

### 採点の物差し（Stage Actor と同じ）

- 3点＝ふつう、4点＝はっきり良い、5点＝際立って良い（めったに付けない）、2点＝弱く修正対象、1点＝ほぼ機能していない

### 判定ゲート

- 合計 **32〜40点：合格**／**28〜31点：要改善**／**27点以下：作り直し**
- 合計点に関係なく、**Hook、Character Voice、Pacing、SEE らしさのいずれかが2点以下なら要改善**
- 観点に × が1つでもあれば要改善

## 6. 感情曲線

- 会話（住人との1回の会話）ごとに、旅人の **緊張・期待・笑い・驚き・共感** を各1〜5で付ける
- `curve_note` に、平らな所・同じ波のくり返しを一言で書く
- SEE は大事件の少ないゲームなので、緊張は低くてよい。見るのは、笑い・共感・驚きが会話ごとに入れ替わっているか

## 7. 不具合

- 必ず問題の台詞を「」で引用する。引用のない指摘は採用しない
- 特に探すもの：言っていない情報を知っている、同じ人物が同時に二か所にいる、帰り道で話が巻き戻る・同じ話を繰り返す、正体を明かす前に正体を前提にした台詞、天候・時間帯と台詞の食い違い
- なければ `bugs: []`

## 8. 出力形式

1つの国＝1行の JSON（JSON Lines）。保存先は `review/results/<回>.jsonl`。

```json
{"id":"hanano","kanten":["○","○","○","○","○","○","○","○"],"axes":[4,3,3,4,3,4,5,4],"total":30,"gate":"要改善","curve":[{"talk":"villager-1","tension":2,"expect":3,"laugh":1,"surprise":2,"empathy":2}],"curve_note":"…","note":"強みと最大の弱点を1〜2文","bugs":[{"quote":"台詞の引用","problem":"なぜ問題か"}]}
```

## 9. 手順

1. `node tools/tx.js` で台本を書き出す
2. `node tools/check.js` で機械チェック。エラーが残っていたら直す
3. 国ごとにレビューして `review/results/<回>.jsonl` に書く
4. `node tools/review_check.js review/results/<回>.jsonl` で、不具合の引用が台本にあるかを照合する
5. ゲートを通らない国は直してから、1 からやり直す。新しい国は、ゲートを通るまで公開しない

## 10. 限界

- 採点は「旅人にその反応が起きやすい構造」の推定で、実測ではない。34点と35点の差に意味はない
- 書いた本人（Claude）が採点すると甘くなりやすい。点は控えめに付け、迷ったら低いほうにする。人のレビューと実際に遊んだ感想が最終判断
